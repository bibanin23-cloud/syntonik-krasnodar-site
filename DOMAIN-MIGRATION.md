# Перенос syntonik-krasnodar.ru с Tilda

**Сейчас ничего не менять. Выполнять только после отдельной команды на перенос и успешной проверки GitHub Pages.** Старый сайт на Tilda сохраняется.

## Подготовка

Сохраните снимок текущих DNS в REG.RU для возврата на Tilda. Текущие IP Tilda здесь не подставлены: их чтение в рабочей среде ограничено. Не меняйте NS, записи почты MX, SPF/DKIM/DMARC, TXT-подтверждения и остальные поддомены.

## В день переключения

1. В [GitHub → Settings → Pages](https://github.com/bibanin23-cloud/syntonik-krasnodar-site/settings/pages) впишите **Custom domain: syntonik-krasnodar.ru** и сохраните. До переноса поле оставляем пустым: иначе временный адрес начнёт перенаправлять на основной домен.
2. В [Actions → Publish and verify Pages](https://github.com/bibanin23-cloud/syntonik-krasnodar-site/actions/workflows/pages.yml) нажмите **Run workflow**, ветка main, тестовую заявку оставьте выключенной. Дождитесь успешных build и deploy: сборка сама переходит на корень домена. Проверка опубликованного сайта до изменения DNS может увидеть старую Tilda; повторите её после переключения.
3. В REG.RU → домен → управление DNS замените только старые **A/AAAA/ALIAS/ANAME у @** и запись **www**, направлявшие сайт на Tilda. Уберите все прежние адреса этих двух имён, иначе часть посетителей попадёт на старый сайт. Не удаляйте записи других служб.
4. Добавьте записи из таблицы. `@` — сам домен, в REG.RU может обозначаться пустым полем. TTL можно оставить 300–3600 секунд, если интерфейс позволяет.

| Тип | Имя | Значение |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | bibanin23-cloud.github.io. |

IPv6 необязателен. Если нужен, добавьте четыре AAAA у @: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`. Старые AAAA Tilda уберите даже без новых AAAA. У www не должно быть A/AAAA одновременно с CNAME. Значение CNAME без https://, пути и имени репозитория.

## Проверка переключения

- В GitHub Pages дождитесь успешной DNS-проверки, затем включите **Enforce HTTPS**, когда станет доступно. Обновление DNS и выпуск сертификата могут занять до суток.
- В Windows: `Resolve-DnsName syntonik-krasnodar.ru -Type A` и `Resolve-DnsName www.syntonik-krasnodar.ru -Type CNAME`. Сравните с таблицей.
- Откройте https://syntonik-krasnodar.ru/ в приватном окне и с телефона через мобильную сеть. Должны появиться новая версия и HTTPS без предупреждений. www должен вести на адрес без www.
- Проверьте 11 экранов, изображения, FAQ, калькулятор, PDF, ссылки и одну тестовую заявку: строка в Таблице, сообщение в Telegram, ничего в MAX. Личная ссылка MAX остаётся.
- Повторите workflow без тестовой заявки: проверка теперь должна пройти на новом домене. Проверьте `/robots.txt`, `/sitemap.xml`, canonical. Индексация главной открывается только при настройке основного домена; блог-заглушка и юридические страницы остаются noindex.

При сбое верните сохранённые записи Tilda. DNS-кэш обновляется постепенно; проверяйте из нескольких сетей.

**Почему нужна настройка GitHub:** при публикации через Actions файл CNAME не подключает домен. Custom domain нельзя включить заранее и сохранить временный адрес без редиректа. Поэтому остаются настройка домена в GitHub, повторная сборка, DNS и проверка HTTPS; одной заменой DNS перенос не ограничивается.

Источник значений: [официальная инструкция GitHub Pages](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).
