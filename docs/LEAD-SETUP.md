# Подключение заявок Syntonik: подробная инструкция

Актуальность проверена 7 октября 2026 года. Это инструкция для уже подготовленного проекта сайта. Сам сайт, его экраны, домен и хостинг при выполнении этих шагов не переделываются.

## Что в итоге будет происходить

Посетитель заполняет существующую форму заказа или обратного звонка и нажимает «Отправить». Заявка сохраняется в вашей Google-таблице, затем обработчик независимо отправляет её в Telegram и MAX. На сайте появляется подтверждение.

**Код уже подготовлен; реальная цепочка пока не подключена.** Проверены 16 сценариев с имитацией внешних сервисов. Реальную запись в вашу таблицу и доставку вашим ботам проверим после настройки аккаунтов. Пока адрес обработчика не указан, сайт сообщает, что онлайн-приём заявок не подключён.

В этой сессии у Codex нет подключённого доступа к вашим Google-аккаунтам и настройкам ботов. Поэтому он не может сейчас создать эти объекты от вашего имени или подтвердить ваши разрешения. Пароли, коды входа и токены в переписку присылать не нужно.

## С чего начать

Удобнее выполнять настройку на компьютере. Держите открытыми эту инструкцию, Google-таблицу и редактор Apps Script. Telegram и MAX можно использовать на телефоне.

Используйте один Google-аккаунт для таблицы, скрипта и выдачи разрешений. Если в браузере несколько Google-аккаунтов, проверяйте аватар справа сверху перед каждым этапом.

Для первого теста уведомления будут приходить лично вам от новых ботов. Настраивать группы и каналы сейчас не требуется. Существующие личные ссылки Telegram/MAX в контактах сайта не являются ботами; менять их не нужно.

Несколько терминов простыми словами:

| Термин | Что это |
| --- | --- |
| Google Sheets | Онлайн-таблица с заявками |
| Google Sheet ID | Часть адреса, по которой скрипт находит именно вашу таблицу |
| Apps Script | Небольшой обработчик, работающий у Google |
| Токен бота | Секретный ключ, который разрешает отправлять сообщения от имени бота |
| Chat ID / User ID | Числовой адрес получателя уведомления; это не номер телефона и не имя пользователя |
| Свойства скрипта / Script Properties | Настройки обработчика, где будут лежать ID и токены |
| Web App URL | Адрес опубликованного обработчика, на который сайт отправляет заявку |
| UTM | Метки источника перехода, например название рекламной кампании |

## Шаг 1. Создайте Google-таблицу

1. Откройте [Google Таблицы](https://sheets.google.com/) и войдите в выбранный аккаунт.
2. Создайте пустую таблицу — обычно это плитка с плюсом «Пустая таблица».
3. Слева сверху замените «Новая таблица» на **Заявки Syntonik**.
4. Оставьте таблицу закрытой. В настройках общего доступа не включайте «Все, у кого есть ссылка». Для приёма заявок публичная таблица не требуется.
5. Заголовки и строки вручную не заполняйте: обработчик создаст их после первой заявки.
6. Посмотрите адрес таблицы в строке браузера. Он имеет такой вид:

   `https://docs.google.com/spreadsheets/d/ЗДЕСЬ_ID_ТАБЛИЦЫ/edit`

7. Скопируйте только участок **после `/d/` и перед следующим `/`**. Не включайте `/edit`, другие параметры или весь адрес.

Условный пример: из адреса `https://docs.google.com/spreadsheets/d/ABC123_example/edit#gid=0` нужно взять `ABC123_example`. Это пример, а не ID для настройки.

**Результат:** у вас открыта пустая таблица «Заявки Syntonik», и вы знаете её ID.

## Шаг 2. Создайте обработчик и вставьте готовый код

В открытой таблице выберите **Расширения → Apps Script**. Откроется редактор в новой вкладке. Если редактор не открывается, проверьте, разрешено ли браузеру открыть новую вкладку.

Назовите проект **Syntonik — заявки**. Название помогает найти проект позже и узнать его в окне выдачи разрешений.

### 2.1. Основной файл

Готовый файл находится в проекте:

`integrations/apps-script/Code.gs`

Его можно открыть [в GitHub](https://github.com/bibanin23-cloud/syntonik-krasnodar-site/blob/main/integrations/apps-script/Code.gs). Репозиторий закрытый: нужно войти в свой GitHub-аккаунт. На странице файла используйте **Raw**, чтобы видеть только код; затем выделите его целиком и скопируйте. Либо откройте локальный файл в текстовом редакторе:

`C:\Users\79951\.codex\.chatgpt-projects\g-p-6ac4fe381c5c819196a2843ded0507c0\syntonik-site\integrations\apps-script\Code.gs`

В Apps Script:

1. Слева откройте существующий файл `Code.gs` — в русском интерфейсе название может отображаться иначе.
2. Щёлкните внутри области кода.
3. Нажмите `Ctrl+A`, затем вставьте скопированное через `Ctrl+V`. Это заменит стандартную функцию, которую Google создал при открытии проекта.
4. Сохраните через `Ctrl+S` или кнопку сохранения, если она отображается.
5. Убедитесь, что нет отметки о несохранённых изменениях.

Не добавляйте к коду поясняющий текст, название файла или тройные обратные кавычки. Вставляется только содержимое файла. Не нажимайте «Выполнить» для `doPost`: она должна запускаться заявкой с сайта, а не вручную.

### 2.2. Файл настроек

1. Слева нажмите шестерёнку **Настройки проекта**.
2. Включите **Показывать файл манифеста appsscript.json в редакторе**; английский вариант — **Show appsscript.json manifest file in editor**.
3. Вернитесь в **Редактор** — значок кода слева.
4. В списке файлов откройте появившийся `appsscript.json`.
5. Замените его содержимое следующим текстом и сохраните:

```json
{
  "timeZone": "Europe/Moscow",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/script.external_request"
  ]
}
```

Вставляйте текст от первой `{` до последней `}` без строки `json` и без кавычек вокруг всего блока. Этот файл задаёт московское время и доступ к таблицам/отправке запросов. [Как открыть манифест в редакторе — Google](https://developers.google.com/apps-script/concepts/manifests).

**Результат:** основной код и файл настроек сохранены в вашем проекте Apps Script.

## Шаг 3. Укажите таблицу в свойствах скрипта

1. Откройте **Настройки проекта**.
2. Прокрутите до раздела **Свойства скрипта / Script Properties**.
3. Нажмите **Добавить свойство / Add script property**.
4. В поле названия вставьте `GOOGLE_SHEET_ID`.
5. В поле значения вставьте ID таблицы из шага 1.
6. Сохраните свойства соответствующей кнопкой.

Название копируется точно, заглавными буквами и с подчёркиваниями. Значение вставляется без кавычек и лишних пробелов. [Управление свойствами — Google](https://developers.google.com/apps-script/guides/properties).

Необязательное свойство `SHEET_NAME` можно не добавлять. Тогда обработчик создаст вкладку **Заявки** внутри вашей таблицы. Название всей таблицы и название вкладки внизу — разные вещи.

На следующих этапах добавляйте новые свойства в этот же раздел. Уже заполненный `GOOGLE_SHEET_ID` сохраняйте.

## Шаг 4. Создайте Telegram-бота

### 4.1. Получите токен

1. Откройте официальный [@BotFather](https://t.me/BotFather).
2. Нажмите **Старт** и отправьте `/newbot`.
3. Укажите отображаемое название, например **Заявки Syntonik**.
4. Затем укажите уникальное имя латиницей с окончанием `bot`, например `EnerDarSyntonikNotifyBot`. Если оно занято, выберите другое.
5. BotFather выдаст токен. Скопируйте весь токен, включая часть до двоеточия и после него.
6. В свойствах Apps Script добавьте `TELEGRAM_BOT_TOKEN`, вставьте токен в значение и сохраните.

Токен хранится здесь, а не в файлах сайта. [Создание бота — Telegram](https://core.telegram.org/bots/features#botfather).

### 4.2. Начните диалог со своим ботом

В сообщении BotFather найдите ссылку на нового бота и откройте её. **Теперь нужен ваш бот, а не BotFather.** Нажмите «Старт» и отправьте сообщение `Тест Syntonik` с того Telegram-аккаунта, куда должны приходить заявки.

Отсутствие ответа сейчас нормально: мы подготовили отправку уведомлений с сайта, а не ответы на сообщения пользователей боту.

### 4.3. Узнайте числовой ID получателя

1. В Apps Script откройте **Редактор** и основной файл кода.
2. На верхней панели рядом с «Выполнить» найдите список функций.
3. Выберите **showRecipientIds**. Если функции нет в списке, сохраните код и обновите редактор.
4. Нажмите **Выполнить**.
5. При первом запуске Google попросит разрешения. Выполните шаг 5 ниже, затем при необходимости снова запустите `showRecipientIds`.
6. В **Журнале выполнения** найдите строку вида `TELEGRAM_CHAT_ID: 123456789`.
7. Скопируйте только число после двоеточия.
8. В **Настройки проекта → Свойства скрипта** добавьте `TELEGRAM_CHAT_ID`, вставьте число и сохраните.

Число `123456789` приведено как пример. Используйте число из своего журнала. Помощник выводит ID, а не токены или тексты сообщений. Если ID не появился, отправьте своему боту ещё одно сообщение и повторите запуск. Если выводов несколько, для простого теста пишите новому боту только со своего аккаунта.

**Результат:** в свойствах сохранены `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

## Шаг 5. Разрешите работу своему скрипту

Этот шаг выполняется при первом запуске помощника или при публикации обработчика — когда Google покажет окно запроса.

1. Нажмите **Просмотреть разрешения / Review permissions**.
2. Выберите тот Google-аккаунт, в котором созданы таблица и скрипт.
3. Проверьте название: разрешение выдаётся вашему проекту **Syntonik — заявки**.
4. Разрешите доступ к Google Таблицам и внешним запросам. Если показаны отдельные флажки для разрешений, отметьте необходимые.
5. Подтвердите действие кнопкой **Разрешить / Allow**.

Доступ к таблицам нужен для сохранения заявки; внешние запросы — для Telegram и MAX. [Как Google запрашивает разрешения](https://developers.google.com/apps-script/guides/services/authorization).

Если появляется **«Google не проверил это приложение»**, это может быть предупреждением о вашем собственном скрипте. Проверьте название проекта и свою учётную запись. Если доступна ссылка **Дополнительные настройки / Advanced**, через неё можно перейти к вашему проекту и выдать разрешения. Это относится только к созданному вами проекту с кодом из этого репозитория. Если Google показывает блокировку без возможности продолжить, пришлите текст ошибки: для рабочего аккаунта могут действовать ограничения администратора. [Объяснение предупреждения — Google](https://developers.google.com/apps-script/guides/client-verification).

**Результат:** выполнение `showRecipientIds` заканчивается, журнал доступен, разрешения выданы.

## Шаг 6. Создайте MAX-бота

### 6.1. Подтвердите профиль бизнеса

1. Откройте [MAX для бизнеса](https://business.max.ru/).
2. Зарегистрируйтесь по доступному вам рабочему номеру и подтвердите вход кодом SMS.
3. Создайте профиль **ИП**, если используете своё ИП. Для этой платформы также предусмотрены профили организаций и самозанятых — резидентов РФ.
4. Пройдите подтверждение профиля. Для ИП доступны Госуслуги либо предлагаемые платформой банковские способы — T-Business ID / Alfa ID.
5. При выборе Госуслуг используйте профиль вашего ИП, а не только личный профиль физического лица.
6. Дождитесь отметки, что профиль подтверждён.

Вход, подтверждение ИП и коды выполняете вы. [Официальные шаги регистрации и подтверждения MAX](https://dev.max.ru/docs/maxbusiness/connection).

### 6.2. Создайте бота и дождитесь проверки

В профиле откройте **Чат-боты → Создать**. Укажите название и описание; загрузите квадратный логотип. Платформа требует изображение 500×500, JPG/PNG, до 5 МБ. Никнейм создаётся автоматически.

Для нашего сценария можно использовать название **ЭнерДар заявки** и описание: **«Служебный бот компании ЭнерДар для уведомлений о заявках с сайта Syntonik. Сообщения получает ответственный сотрудник.»** Это описание отражает подготовленную функцию; одобрение платформы не гарантируется.

Отправьте бота на проверку. Пока она идёт, выполняйте остальные шаги Google и Telegram. Если требуются исправления, смотрите причину в карточке бота. [Создание и проверка бота — MAX](https://dev.max.ru/docs/chatbots/bots-create/create).

Если для аватара нужно подготовить квадратную версию вашего логотипа, это может сделать Codex по имеющемуся исходнику. В рамках этой инструкции новый графический файл не создавался.

### 6.3. Получите токен

После успешной проверки откройте **Чат-боты → ваш бот → ⋮ → Настройки**. Справа от токена нажмите копирование. Добавьте в свойства Apps Script `MAX_BOT_TOKEN`, вставьте токен и сохраните. [Где получить токен — MAX](https://dev.max.ru/docs/chatbots/bots-create/manage).

### 6.4. Укажите личного получателя

1. Откройте ссылку именно на нового бота MAX из его карточки.
2. Начните диалог с того MAX-аккаунта, куда хотите получать заявки, и отправьте `Тест Syntonik`, если поле сообщения доступно.
3. Сразу после этого запустите **showRecipientIds** в Apps Script.
4. Найдите в журнале строку `MAX_USER_ID: ...`.
5. Скопируйте число после двоеточия.
6. Добавьте свойство **MAX_USER_ID**, вставьте число и сохраните.

Для этого варианта **не добавляйте MAX_CHAT_ID**. В подготовленном коде он имеет приоритет над MAX_USER_ID, поэтому для личного получателя достаточно одного MAX_USER_ID. Личная ссылка из контактов сайта не заменяет числовой ID.

Если ID не появился, начните диалог/отправьте сообщение повторно и снова запустите помощник. Он использует получение последнего события для настройки нового тестового бота без подписки на webhook; постоянный опрос для работы сайта не нужен. Если бот уже подключён к другой системе, сообщите об этом перед изменением его настроек. [Получение событий при тестировании — MAX](https://dev.max.ru/docs-api/methods/GET/updates).

**Результат:** в свойствах сохранены `MAX_BOT_TOKEN` и `MAX_USER_ID`.

### Если MAX ещё проходит проверку

Чтобы начать промежуточный тест таблицы и Telegram, добавьте `MAX_ENABLED` со значением `false` и сообщите Codex, что MAX пока отключён. Считать всю цепочку готовой до проверки MAX нельзя.

После получения токена и ID измените `MAX_ENABLED` на `true` или удалите только это свойство и сохраните настройки. Не удаляйте остальные свойства. Новую версию обработчика при изменении одних свойств выпускать не требуется.

## Шаг 7. Проверьте настройки перед публикацией

Для полной проверки личных уведомлений должно быть заполнено:

| Название свойства | Что вставить |
| --- | --- |
| `GOOGLE_SHEET_ID` | ID таблицы из её адреса |
| `TELEGRAM_BOT_TOKEN` | Токен, который выдал BotFather |
| `TELEGRAM_CHAT_ID` | Число из журнала помощника для Telegram |
| `MAX_BOT_TOKEN` | Токен из настроек опубликованного MAX-бота |
| `MAX_USER_ID` | Число из журнала помощника для вашего MAX-аккаунта |

`SHEET_NAME` необязателен; без него используется вкладка «Заявки». `TELEGRAM_ENABLED` и `MAX_ENABLED` тоже необязательны: отсутствие этих свойств означает, что код пытается отправлять уведомления. Значение `false` отключает соответствующий канал.

Проверьте, что значения вставлены полностью, без кавычек. Имя свойства и значение находятся в разных полях. Все свойства должны быть сохранены **в одном проекте Apps Script**, в который вставлен наш код.

## Шаг 8. Опубликуйте обработчик

1. В Apps Script нажмите **Развернуть / Deploy → Новое развертывание / New deployment**.
2. Выберите тип **Веб-приложение / Web app** — при необходимости через шестерёнку выбора типа.
3. Укажите описание, например **Тест заявок Syntonik**.
4. Выполнять от имени: **Я / Me** — ваш Google-аккаунт.
5. Доступ: **Все / Anyone**, включая посетителей без входа в Google. Вариант «Все пользователи с аккаунтом Google» не подходит.
6. Нажмите **Развернуть** и подтвердите разрешения, если Google снова их запросит.
7. Скопируйте **URL веб-приложения** вида `https://script.google.com/macros/s/АДРЕС_РАЗВЕРТЫВАНИЯ/exec`.

Таблица остаётся закрытой: опубликован обработчик. Адрес редактора, ID развертывания и ссылка с `/dev` для подключения формы не подходят. [Публикация веб-приложения — Google](https://developers.google.com/apps-script/guides/web).

### Проверьте ссылку

Откройте новое приватное окно браузера — обычно `Ctrl+Shift+N` в Chrome/Edge — и вставьте скопированный URL `/exec`. Должно появиться:

```json
{"success":true,"service":"Syntonik leads"}
```

**Это проверка доступности адреса.** Она ещё не подтверждает правильность ID таблицы, запись заявки или отправку ботам. При простом открытии ссылки строка в таблице не создаётся.

Если появляется вход в Google или отказ в доступе, настройки публикации не подходят для формы. Проверьте выбранный вариант доступа. Если варианта «Все» нет, пришлите текст доступных вариантов — для рабочего аккаунта возможны ограничения.

**Теперь пришлите Codex только полный URL с `/exec`.** Можно написать: «Обработчик опубликован: [адрес]. MAX настроен» либо «MAX пока отключён и проходит проверку».

Токены, пароли и коды не присылайте. ID таблицы и получателей уже находятся в свойствах; для изменения сайта они Codex не нужны.

## Шаг 9. Подключение сайта — это сделает Codex

После получения ссылки Codex укажет её в существующем `public/lead-config.js`, проверит подключение форм и сохранит изменение в GitHub. Самостоятельно редактировать JavaScript сайта вам не нужно.

На этом этапе домен, DNS и размещение сайта не меняются. Испытание проводим в текущем предпросмотре.

До сообщения Codex о подключении адреса тестировать отправку через сайт рано: опубликованный Apps Script сам по себе не меняет конфигурацию сайта.

## Шаг 10. Отправьте одну тестовую заявку

### 10.1. Откройте чистую сессию

После подключения адреса закройте прежние приватные окна и откройте новое. На том же компьютере, где работает предпросмотр, вручную вставьте в адресную строку:

`http://127.0.0.1:4173/?utm_source=test&utm_medium=manual&utm_campaign=syntonik&utm_content=order&utm_term=check`

Первые метки сохраняются на время вкладки. Поэтому обычное обновление старой вкладки не всегда заменит ранее сохранённые метки. Ссылка `127.0.0.1` доступна на этом компьютере; на телефоне она не открывает ваш компьютер. Если предпросмотр не работает, Codex восстановит его.

### 10.2. Заполните существующую форму

Нажмите «Заказать». Введите, например:

| Поле | Тестовое значение |
| --- | --- |
| Имя | Тест Syntonik |
| Телефон | Ваш доступный тестовый контакт в обычном формате телефона |
| Тип топлива | Бензин |
| Объём | 250 мл |
| Город | Краснодар |

Отметьте существующие согласия. Отдельного поля комментария в текущей форме нет; город, топливо и объём обработчик добавит в комментарий сам. Нажмите **Отправить** один раз.

Пока запрос выполняется, кнопка должна быть недоступна для повторного нажатия. При подтверждённой записи появится **«Спасибо! Заявка отправлена.»**, форма очистится, страница не перезагрузится.

### 10.3. Проверьте три места

1. **Google-таблица:** появилась вкладка «Заявки», 12 заголовков и одна строка. Статус — «Новая», форма — `order`, в комментарии — город/топливо/объём. Метки: `test`, `manual`, `syntonik`, `order`, `check`. Время — московское.
2. **Telegram:** пришло одно сообщение от вашего нового бота с теми же данными.
3. **MAX:** пришло одно аналогичное сообщение от вашего MAX-бота.

Подтверждение на сайте означает, что заявка сохранена в таблице. Оно не доказывает доставку обоим ботам: сбой мессенджера специально не мешает сохранению заявки. Поэтому сообщения проверяются отдельно.

Если MAX временно отключён, на этом этапе ожидаются таблица и Telegram; полную проверку повторим после включения MAX.

### 10.4. Проверьте обратный звонок

Нажмите «Заказать обратный звонок», заполните имя/телефон/город, поставьте согласие и отправьте. Должна появиться ещё одна строка, форма — `callback`; уведомления — об обратном звонке. Выбранного товара в этой заявке нет.

Дополнительно в свежей приватной сессии можно открыть ссылку с UTM, перейти в блог и вернуться на главную в той же вкладке. После отправки метки первого перехода должны сохраниться.

**Полная цепочка проверена, когда одна отправка создаёт одну строку и по одному сообщению в обоих мессенджерах, а заказ и обратный звонок проходят отдельно.**

## Если что-то не получилось

| Что видите | Что проверить или сообщить Codex |
| --- | --- |
| На сайте всё ещё написано, что онлайн-приём не подключён | Передана ли ссылка `/exec` и подтвердил ли Codex её подключение; затем обновите страницу |
| При открытии `/exec` требуется вход в Google | Настройки доступа веб-приложения: нужен анонимный доступ |
| `showRecipientIds` отсутствует | Основной код вставлен целиком и сохранён; обновите редактор |
| Помощник не вывел ID Telegram | Написали ли вы своему новому боту, а не BotFather; верно ли сохранён токен |
| Помощник не вывел ID MAX | Пройдена ли проверка бота, сохранён ли токен; начните диалог и сразу повторите помощник |
| Ошибка отправки на сайте, строки нет | Сохранён ли ID таблицы, выбран ли тот же Google-аккаунт, выданы ли разрешения; откройте «Выполнения» в Apps Script |
| Ошибка на сайте, но строка есть | Возможно, ответ не дошёл до браузера. Сообщите результат Codex; не создавайте новую таблицу или бота |
| Строка есть, Telegram отсутствует | Проверьте его токен и Chat ID, что бот начат и не заблокирован; нет ли `TELEGRAM_ENABLED=false` |
| Строка есть, MAX отсутствует | Проверьте токен/личный User ID, что бот начат; нет ли `MAX_ENABLED=false` или лишнего `MAX_CHAT_ID` |
| В таблице пустые или старые UTM | Убедитесь, что тест начат в новой приватной сессии с указанной ссылкой |
| В свойствах исправили токен, но старое уведомление не появилось | Автоматической повторной доставки старого сообщения нет. Проверьте новую тестовую заявку после исправления |

Для помощи достаточно сообщить номер шага, текст ошибки и где появился результат: сайт/таблица/Telegram/MAX. При скриншотах настроек закройте токены. Текст из раздела «Выполнения» можно прислать без секретов и контактов реальных клиентов.

При ошибке сайта введённые данные остаются в форме. Повтор той же заявки после сетевой ошибки защищён от второй строки. После успешной отправки новое заполнение создаёт новую заявку. В ячейке «Статус» обработчик хранит служебное примечание для защиты от дублей; его не удаляйте.

## Что делать при будущих изменениях

Если изменены только токен или ID в свойствах: сохраните свойства и отправьте новую тестовую заявку.

Если Codex исправил основной код Apps Script: вставьте обновлённый код, сохраните, откройте **Развернуть → Управление развертываниями**, выберите действующее развертывание, нажмите редактирование, выберите **Новую версию** и разверните. Можно сохранить прежний URL. Одного сохранения кода недостаточно для обновления опубликованной версии. [Обновление развертывания — Google](https://developers.google.com/apps-script/concepts/deployments).

Если создали новое развертывание с другим URL: пришлите новый адрес Codex, чтобы он обновил сайт.

Для повседневного приёма заявок редактор и таблицу не нужно держать открытыми. Google выполняет опубликованный обработчик на своей стороне. Текущий локальный предпросмотр сайта при этом должен работать, чтобы открыть и отправить форму с него.
