# Тестовый сбор заявок Syntonik

Код подготовлен для существующих форм заказа и обратного звонка. Внешние аккаунты ещё не настроены. До заполнения `LEAD_ENDPOINT` сайт показывает прежнее уведомление, что онлайн-приём не подключён; отправка не имитируется.

## 1. Google Sheets и Apps Script

1. В своём Google-аккаунте создайте **закрытую** таблицу «Заявки Syntonik». Публичный доступ к таблице не требуется.
2. Скопируйте ID из её адреса: `https://docs.google.com/spreadsheets/d/ЗДЕСЬ_ID/edit`.
3. В таблице откройте **Расширения → Apps Script**.
4. Замените содержимое `Code.gs` кодом из `integrations/apps-script/Code.gs` этого проекта. Сохраните.
5. В настройках проекта включите отображение файла манифеста `appsscript.json` и замените его содержимое файлом `integrations/apps-script/appsscript.json`.
6. В **Настройки проекта → Свойства скрипта** добавьте параметры из таблицы ниже. Токены вставляйте только туда, а не в сайт, GitHub или переписку.

| Свойство | Значение |
| --- | --- |
| `GOOGLE_SHEET_ID` | ID вашей Google-таблицы |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | Числовой ID чата, куда бот отправляет заявки |
| `MAX_BOT_TOKEN` | Токен MAX-бота |
| `MAX_CHAT_ID` | Числовой ID чата/канала MAX; для личного получателя можно вместо него задать `MAX_USER_ID` |
| `SHEET_NAME` | Необязательно; по умолчанию `Заявки` |

Для независимого временного отключения канала добавьте `TELEGRAM_ENABLED=false` или `MAX_ENABLED=false`. Отсутствующие токены считаются ненастроенным каналом, а не успешной доставкой. Для проверки всей цепочки оба канала должны быть настроены и включены.

При первом POST обработчик создаст лист «Заявки» и 12 заголовков: дата и время, имя, телефон/контакт, комментарий, форма, страница, пять UTM-параметров и статус. Новая строка получает статус «Новая». Время записывается по серверу, часовой пояс — Москва. Город, выбранные топливо и фасовка сохраняются в колонке «Комментарий» и в уведомлениях, без добавления полей на сайте.

## 2. Telegram

1. Откройте официальный [@BotFather](https://t.me/BotFather), выполните `/newbot` и создайте бота. Сохраните выданный токен в `TELEGRAM_BOT_TOKEN`.
2. Откройте **своего нового бота**, нажмите «Старт» и отправьте ему любое сообщение. Если получателем будет группа, добавьте туда бота и отправьте команду в группе.
3. В редакторе Apps Script выберите функцию `showRecipientIds` и нажмите **Выполнить**. При первом запуске разрешите доступ скрипта к таблицам и внешним запросам.
4. В журнале выполнения найдите `TELEGRAM_CHAT_ID` нужного чата и перенесите его в свойства скрипта. Отрицательный знак ID группы сохраняйте.

Функция только читает события ботов и выводит идентификаторы. Токены и тексты сообщений она в журнал не записывает. Если ID не появился, отправьте боту новое сообщение и повторите запуск.

Официальная документация: [создание бота](https://core.telegram.org/bots/features#botfather), [метод sendMessage](https://core.telegram.org/bots/api#sendmessage).

## 3. MAX

1. Создайте/подтвердите профиль ИП на [платформе MAX для бизнеса](https://business.max.ru/) и создайте чат-бота. Возьмите его токен в настройках бота и сохраните как `MAX_BOT_TOKEN`.
2. Откройте своего бота в MAX и начните диалог. Для группового чата/канала добавьте бота с необходимыми правами.
3. Сразу после нового события запустите `showRecipientIds` в Apps Script. Скопируйте `MAX_CHAT_ID` нужного чата либо `MAX_USER_ID` получателя в свойства скрипта. Указывайте один способ адресации; `MAX_CHAT_ID` имеет приоритет.
4. Если событие не появилось, повторите действие в MAX и запуск функции. Помощник использует `GET /updates` для настройки тестового бота без webhook; постоянного опроса или webhook в этой схеме нет.

Личная ссылка MAX из контактов сайта не заменяет токен бота или числовой ID получателя. Используется официальный API `https://platform-api2.max.ru`, токен передаётся в заголовке `Authorization`, а не в URL.

Официальная документация: [платформа](https://dev.max.ru/docs), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages), [получение событий для тестирования](https://dev.max.ru/docs-api/methods/GET/updates).

## 4. Публикация обработчика

1. В Apps Script выберите **Развернуть → Новое развертывание → Веб-приложение**.
2. Выполнять от имени: **вас**. Доступ: **Все / Anyone**, включая пользователей без входа в Google. Доступ к самой таблице остаётся закрытым.
3. Подтвердите разрешения своего скрипта и скопируйте URL вида `https://script.google.com/macros/s/…/exec`. Адрес `/dev` для формы не подходит.
4. Откройте URL в приватном окне браузера. Должен появиться JSON `{"success":true,"service":"Syntonik leads"}`, без требования войти в Google.
5. Пришлите Codex **только этот URL Web App**. Он будет указан в `public/lead-config.js` как `LEAD_ENDPOINT`. ID таблицы, токены и ID получателей остаются в свойствах скрипта.
6. После изменения серверного кода обновляйте развертывание через **Управление развертываниями → Изменить → Новая версия**. URL действующего развертывания можно сохранить.

Google: [Web Apps](https://developers.google.com/apps-script/guides/web), [Script Properties](https://developers.google.com/apps-script/guides/properties), [JSON Content Service и перенаправления](https://developers.google.com/apps-script/guides/content).

## 5. Одна тестовая заявка

1. После настройки endpoint откройте сайт в **новой вкладке** с адресом `http://127.0.0.1:4173/?utm_source=test&utm_medium=manual&utm_campaign=syntonik&utm_content=order&utm_term=check`.
2. Перейдите в блог и обратно на главную. Это дополнительно проверяет сохранение первых UTM в пределах вкладки; отсутствие новых UTM не должно их стирать.
3. Нажмите «Заказать», введите вымышленные тестовые данные, город, топливо и фасовку, поставьте согласия и нажмите «Отправить» один раз. Пока запрос выполняется, кнопка заблокирована.
4. На сайте должно появиться **«Спасибо! Заявка отправлена.»**. Страница не перезагружается, форма очищается, кнопка снова доступна.
5. В таблице должна появиться **одна строка** со всеми полями, UTM и статусом «Новая».
6. Проверьте **по одному уведомлению** в Telegram и MAX. Проверьте имя, контакт, город, товар, URL, UTM и московское время.

Повторите проверку через «Заказать обратный звонок»: форма должна записываться как `callback`, без выбранного товара. Для проверки аварийного сценария временно задайте неверный токен одного бота: строка всё равно сохраняется, второй канал получает сообщение. Затем восстановите токен. Обновлять развертывание при изменении только Script Properties не требуется.

## Что считается успехом и как разбирать ошибки

- `success:true` означает, что заявка сохранена в Google Sheets. Статусы независимых уведомлений возвращаются в `notifications`: `sent`, `failed` или `disabled`. В интерфейсе сайта эти служебные сведения не показываются.
- При сбое мессенджера основная заявка остаётся в таблице; в выполнениях Apps Script появляется краткая отметка канала без токена. Автоматическая повторная доставка уведомлений и отдельная очередь в этот тестовый вариант не входят.
- Повторный POST с тем же `request_id` не создаёт новую строку: идентификатор хранится в примечании ячейки статуса. Не удаляйте такие примечания. При сетевой ошибке повторная отправка тех же данных использует прежний ID; после подтверждённого успеха следующая заявка получает новый.
- Ошибка сайта не очищает введённые данные. Проверьте публичность `/exec`, ID таблицы и права скрипта, затем повторите отправку. Если заявка успела сохраниться до потери ответа, примечание с ID предотвращает её повторную запись.
- Клиент отправляет POST с JSON внутри `text/plain` и читает JSON-ответ, следуя перенаправлению Google. Режим `no-cors`, который не позволяет проверить ответ, не используется. Если браузер не даёт прочитать ответ, успех не имитируется: нужен URL развертывания и проверка конкретного ответа Google.
- Первый визит сохраняет только UTM в `sessionStorage`. Контакты и комментарии туда не записываются. При запрете браузерного хранилища UTM доступны на текущей странице, но сохранение между страницами ограничивается настройками браузера.
- Локальная проверка подтверждает логику кода на имитированных сервисах. Реальные права Google, доставку ботов и браузерный ответ можно проверить только после создания аккаунтов, заполнения настроек и подключения `/exec`.

## Файлы и функции

- `public/lead-config.js`: единственный публичный URL `LEAD_ENDPOINT`.
- `public/lib/leads.js`: `captureSessionUtms`, `createLeadSubmitter` → единая `submitLead`; ограничения значений, повторная отправка и чтение подтверждения.
- `public/app.js`: существующие формы заказа/звонка подключены к `submitLead`, добавлены состояния ожидания, успеха и ошибки.
- В HTML главной добавлен идентификатор существующего уведомления настройки; в блог и юридические страницы добавлен невидимый модуль сохранения UTM. Их тексты и дизайн не меняются.
- `scripts/serve.mjs`: в политике безопасности существующего локального превью разрешено соединение с Apps Script и адресом его JSON-ответа. Новый сервер не создаётся.
- `integrations/apps-script/Code.gs`: `doPost`, `normalizeLead`, `leadMessage`, `sendToTelegram`, `sendToMax`, `showRecipientIds`.
- `integrations/apps-script/appsscript.json`: часовой пояс и необходимые разрешения Apps Script.
- `tests/leads.test.mjs`: проверки отправки, UTM, дублей, таблицы и независимости мессенджеров.

Секретные значения и сами заявки в файлы проекта/GitHub не записываются. Доменные настройки и хостинг сайта не изменяются.
